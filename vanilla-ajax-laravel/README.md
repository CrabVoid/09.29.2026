# Vanilla AJAX Project for Laravel API

This small project demonstrates how to use **plain (vanilla) JavaScript** to make AJAX requests to a Laravel back‑end API without reloading the page. The fetched data is rendered into the DOM.

## Project structure
```
vanilla-ajax-laravel/
├─ index.html   # Simple HTML page with a button and container
├─ app.js       # JavaScript – fetch API calls & DOM rendering
└─ README.md    # This file
```

## Prerequisites
1. **Laravel API** running locally (or remotely). The API must expose an endpoint that returns JSON, e.g.:
   ```
   GET /api/items
   ```
   The response should be an array of objects, each having at least `id`, `name`, and optionally `description`.
2. **CORS** enabled on the Laravel side so the browser can call it from a different origin (if you open `index.html` via `file://`). Add the following to your Laravel middleware or use the **fruitcake/laravel-cors** package:
   ```php
   header('Access-Control-Allow-Origin: *');
   header('Access-Control-Allow-Methods: GET, POST, OPTIONS');
   header('Access-Control-Allow-Headers: Content-Type, X-Requested-With');
   ```
   Adjust the origins as needed for production.
3. **Node.js** optional – only if you want to serve the files with a static server (recommended for proper CORS handling). You can use `npx serve` or any other static server.

## Customising the API URL
If your Laravel API runs on a different host/port or has a different base path, edit the constant at the top of `app.js`:
```js
const API_BASE_URL = "http://your-host:port/api";
```

## What the code does
- **`index.html`** – Provides a button (`#loadBtn`) and a container (`#dataContainer`). It loads `app.js`.
- **`app.js`** – Uses the **Fetch API** (modern replacement for `XMLHttpRequest`) to GET JSON data, handles errors, escapes HTML to avoid XSS, and injects the results into the DOM.
- The DOM is updated **without a page reload**, satisfying the AJAX requirement.

## Troubleshooting
- **CORS errors** – Ensure the Laravel API sends the correct `Access-Control-Allow-Origin` header.
- **Network errors** – Verify the API URL is reachable (try it in the browser or with `curl`).
- **Empty response** – The endpoint must return a JSON array; otherwise the UI will show *"No data received."*.
